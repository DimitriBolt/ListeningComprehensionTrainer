# Пробы S00b

Скрипт `probe.py` проверяет с вашим ключом всё, что в разведке S00
(`docs/research/00-models.md`) осталось «не подтверждено». Код приложения не меняется.

## Что нужно

- Ubuntu, Python 3.10 или новее.
- Файл `credentials.properties` в корне репозитория со строкой `APIkey=sk-...`
  (тот же, что для сборки). Скрипт читает ключ только оттуда (другой файл можно указать
  через `--credentials`), нигде его не печатает и не записывает в результаты.

## Установка (один раз)

Из корня репозитория:

```bash
python3 -m venv tools/probe/.venv
source tools/probe/.venv/bin/activate
pip install -r tools/probe/requirements.txt
```

Каталог `tools/probe/.venv/` в `.gitignore`, в git он не попадёт.

## Запуск

```bash
cd tools/probe
python probe.py all          # всё по очереди; сначала покажет оценку цены и спросит «y»
```

Пробы можно запускать и по одной (подробности: `python probe.py <команда> -h`):

| Команда | Что выясняет | Время | Цена |
|---|---|---|---|
| `verbatim` | читает ли `gpt-realtime-2.1-mini` 50 групп дословно; задержка и токены | 3–6 мин | ≈ $0.07, со вторым промптом ≈ $0.13 |
| `latency` | время до первого звука `gpt-realtime-2.1-mini`, 10 групп | < 1 мин | ≈ $0.01 |
| `voices` | одна фраза всеми 10 голосами Realtime | ~1 мин | ≈ $0.02 |
| `tutor` | `gpt-6-luna` с инструментами, 5 реплик | < 1 мин | < $0.01 |
| `transcribe` | как передать `languages` для `gpt-transcribe`; время ответа | < 1 мин | < $0.01 |
| `vadservice` | `semantic_vad` в разговорной сессии без ответов и в сессии транскрипции | ~1 мин | < $0.01 |
| `all` | всё подряд | 7–12 мин | ≈ $0.18 (оценка сверху; бюджет — $1) |

Цены — оценка по прайсу OpenAI, а не счёт. Настоящий расход потом виден в панели
Usage на platform.openai.com.

С S02b пробы не вызывают `tts-1`, `gpt-4o-mini` и `whisper-1`: их отключают 2027-01-06,
2027-01-14 и 2027-02-26. Прежние сравнения с ними остались в `docs/research/00b-results.md`
(перезапуск пробы перепишет её раздел без них).

Полезно для первого пробного запуска (несколько центов, минута):

```bash
python probe.py verbatim --limit 5
```

Фразы «ученика» для `transcribe` и `vadservice` синтезирует `gpt-realtime-2.1-mini` (голос
`alloy`, как синтез в приложении: ответ вне разговора с промптом «читающего движка»).
Свой звук вместо синтезированной фразы ученика — живой голос лучше для пробы `semantic_vad`:

```bash
python probe.py transcribe --wav ~/student.wav          # WAV 16 бит, любая частота
python probe.py vadservice --vad-wav ~/with_pauses.wav   # с паузой ~1,5 с посреди фразы и в конце
```

Записи голоса в репозиторий не кладите — `*.wav` и так в `.gitignore`.

## Что получится

- `tools/probe/out/results.md` — отчёт по всем пробам (с путями к звуку);
- `tools/probe/out/results.json` — сырые данные;
- `tools/probe/out/verbatim/*.wav`, `tools/probe/out/voices/*.wav` — звук;
- `docs/research/00b-results.md` — копия отчёта без путей к звуку, для архитектора.

Каталог `out/` в git не попадает. Каждая команда обновляет свой раздел, остальные
сохраняются; повторный запуск пробы заменяет её раздел.

Если одна проба упала (сеть, таймаут, отказ API), ошибка записывается в её раздел,
а `all` идёт дальше. Ошибка 401 (ключ не принят) останавливает прогон сразу.

## После прогона

1. Послушайте `out/voices/*.wav` и впишите выбранный голос в раздел «voices»
   файла `docs/research/00b-results.md`.
2. В разделе «vadservice» допишите расход из панели Usage за день прогона.
3. Отправьте результаты (из корня репозитория):

   ```bash
   git add docs/research/00b-results.md && git commit -m "[S00b] Результаты проб" && git push
   ```

4. Скажите архитектору: «S00b: результаты в docs/research/00b-results.md».

## Тесты (без ключа и без сети)

```bash
python -m pytest tools/probe/tests
```

`test_probe.py` — ключ, аргументы, нормализация и сравнение текстов, разбиение на группы,
звук, файлы результатов. `test_fake_server.py` гоняет сетевой код против подставного
локального сервера: он ловит ошибки в нашем коде, но не подтверждает, что настоящий API
отвечает так же.

## Откуда 50 групп

`fixtures/teacher_replies.txt` — шесть типичных ответов учителя. `fixtures/chunks.txt`
получен из них функцией `split_into_chunks` — это перенос `TrainerViewModel.splitIntoChunks`
с Kotlin на Python, повторяющий его поведение вместе с особенностями. Пересоздать:

```bash
cd tools/probe && python -c "import probe; probe.write_chunks_fixture()"
```
