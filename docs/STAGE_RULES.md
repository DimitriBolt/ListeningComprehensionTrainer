# Правила для чата-исполнителя этапа

Ты выполняешь один этап проекта. Архитектуру и план ведёт другой чат (архитектор).
Он не видит твой разговор: до него дойдут только коммиты и твой отчёт.

## Перед началом

1. Прочитай `docs/ARCHITECTURE.md`, `docs/PLAN.md` и свой `docs/stages/NN-brief.md`.
2. Если в брифе что-то неясно или противоречит коду, спроси пользователя до начала работы.
3. Напиши пользователю план в 3–7 пунктов и дождись «да».

## Во время работы

- Делай только то, что в брифе. Нашёл проблему за его пределами — запиши в отчёт, не чини.
- Не нарушай инварианты из `docs/ARCHITECTURE.md`. Если бриф требует нарушить — остановись и спроси.
- Коммиты мелкие, прямо в `master`, сообщение начинается с `[SNN]`, например
  `[S01] Вынести запуск записи в сервис`.
- После каждого коммита сразу делай `git push`. Разрешения у пользователя не спрашивай:
  commit и push — действие по умолчанию. Несохранённая в GitHub работа считается несделанной.
- `docs/ARCHITECTURE.md` и `docs/PLAN.md` не редактируй.
- Ключи, токены, записи голоса в репозиторий не клади. Ключ у пользователя не проси.
- Идентификаторы моделей и факты об API бери из официальной документации, которую
  прочитал сейчас, а не по памяти: модели быстро меняются.

## Сложность и уборка

- Если задача заметно усложняет архитектуру, добавляет зависимостей, настроек или
  сквозной логики, не делай это молча: предупреди пользователя, объясни, откуда цена,
  и предложи вариант проще, который даёт большую часть пользы.
- Предпочитай простое и прямое решение преждевременной абстракции.
- В той области, которую трогаешь, удаляй мёртвый код, неиспользуемые функции,
  устаревшие комментарии и настройки. Если удалять рискованно — напиши об этом в отчёте.

## Сборка и проверка

- Попробуй собрать проект и запустить тесты. Если в твоей среде это невозможно,
  так и напиши в отчёте — не пиши «собирается», если не собирал.
- Для чистой логики (без Android) пиши модульные тесты.
- Составь для пользователя ручную проверку на телефоне: шаги и ожидаемый результат.

## Отчёт

В конце положи `docs/stages/NN-report.md` по шаблону и скажи пользователю, что этап готов.

```markdown
# Отчёт S NN — <название>

## Сделано
- …

## Коммиты
- <хеш> <сообщение>

## Отклонения от брифа
- что сделано иначе и почему (или «нет»)

## Не сделано
- что из брифа осталось и почему (или «нет»)

## Как проверено
- сборка: собрал / не смог собрать (причина)
- тесты: какие, результат
- время от конца реплики ученика до первого звука учителя: до … / после … (или «не измерял», причина)

## Ручная проверка для пользователя
1. шаг → ожидаемый результат

## Замечено за пределами этапа
- …

## Вопросы к архитектору
- …
```
