# Бриф S00b — Пробы с ключом

Стартовая фраза для нового чата:

> Ты исполнитель этапа S00b проекта github.com/DimitriBolt/ListeningComprehensionTrainer.
> Прочитай в репозитории `docs/STAGE_RULES.md`, `docs/ARCHITECTURE.md`, `docs/PLAN.md`,
> `docs/research/00-models.md` и `docs/stages/00b-brief.md` и выполни задание из брифа.

## Зачем этап

Разведка S00 (`docs/research/00-models.md`) оставила пункты «не подтверждено», которые
решаются только настоящими запросами к OpenAI. От главного из них — читает ли
`gpt-realtime-2.1-mini` заданный текст дословно — зависит, какой синтез будет основным в S02.

У исполнителя ключа нет и не будет. Поэтому ты пишешь **скрипт**, а запускает его
пользователь на своём компьютере (Ubuntu, Python 3). Код приложения не меняется.

## Что сделать

Каталог `tools/probe/`:

- `probe.py` — один скрипт, подкоманды (см. ниже), `--help` на русском;
- `requirements.txt` — минимум зависимостей (например, `websockets`, `httpx` или `requests`);
- `README.md` — как запустить: venv, установка, команда, сколько это стоит, сколько длится;
- `fixtures/chunks.txt` — 50 смысловых групп, как их режет нынешний `splitIntoChunks`
  (возьми 6–8 типичных ответов учителя и прогони через ту же логику — можно переписать её
  на Python, пометив это). Обязательно включи вопросы, повелительные фразы, обрывки из
  2–3 слов («and then,», «What do you think?», «Tell me more.»), числа и даты;
- `fixtures/student.wav` и т. п. **не создавай** — записи голоса в репозиторий не кладём.
  Для проверки распознавания скрипт сам синтезирует фразу ученика (любой моделью) или
  берёт путь к WAV из аргумента.

### Ключ

Скрипт читает ключ из `credentials.properties` в корне репозитория, строка `APIkey=...`
(путь можно переопределить `--credentials`). Ключ нигде не печатается, не пишется в
файлы результатов и в логи. При ошибке 401 — понятное сообщение без ключа.

### Подкоманды (ответы на вопросы из S00)

1. **`verbatim`** — главная проба (вопрос 5 разведки). Для каждой группы из
   `fixtures/chunks.txt`: Realtime-сессия `gpt-realtime-2.1-mini` по WebSocket в роли
   «движка синтеза» (приём из `[V2]`: инструкции сессии — синтезатор, текст — сообщением
   пользователя, ответ вне разговора, только звук). Сравнить текст группы с
   `response.output_audio_transcript.done` после нормализации (регистр, пунктуация,
   числа). Записать: дословно / расхождение (какое), время от `response.create` до
   первого `response.output_audio.delta`, время до конца звука, токены из `response.done`.
   Опционально второй вариант промпта, если первый даёт < 98 % дословных.
2. **`latency`** — сравнить время до первого звука: `tts-1` (пока работает) против
   `gpt-realtime-2.1-mini` на 10 одинаковых группах; медиана и максимум.
3. **`voices`** — синтезировать одну и ту же фразу всеми голосами Realtime со скоростью
   0.88; сохранить WAV в `tools/probe/out/voices/` (каталог `out/` в `.gitignore`) —
   пользователь выберет голос на слух. Для сравнения — та же фраза голосом `nova` через `tts-1`.
4. **`tutor`** — `gpt-6-luna` через `/v1/chat/completions` с `reasoning_effort: "none"` и
   нынешними `tools` (`get_weather`, `search_live_web` — схемы скопировать из
   `TrainerViewModel.kt`), 5 реплик ученика, одна из которых требует поиска. Проверить,
   что формат `tool_calls` и сообщений `tool` прежний. Сохранить ответы рядом с ответами
   `gpt-4o-mini` на те же реплики — для сравнения качества глазами.
5. **`transcribe`** — `gpt-transcribe` через `/v1/audio/transcriptions`: выяснить, как
   передать `languages` в multipart (перебрать 2–3 варианта, записать, какой принят);
   время ответа против `whisper-1` на одном и том же WAV.
6. **`vadservice`** — гипотеза «VAD как услуга» (раздел «Сравнение вариантов»):
   разговорная сессия с `semantic_vad` (`eagerness: low`), `create_response: false`,
   `interrupt_response: false`, расшифровка входа `gpt-transcribe`. Подать WAV с паузой
   1,5 с посреди фразы и в конце. Записать: приняла ли сессия настройки, какие события
   пришли и когда (`speech_started`, `speech_stopped`, `committed`, расшифровка), был ли
   конец реплики на паузе посреди фразы; расход из `response.done`/отчёта об использовании,
   если он есть. Также проверить, принимает ли сессия транскрипции с `gpt-transcribe`
   `turn_detection: semantic_vad`.
7. **`all`** — всё по очереди.

Каждая подкоманда дописывает свой раздел в `tools/probe/out/results.md` (машиночитаемые
сырые данные — в `out/results.json`). В конце скрипт печатает, что пользователю сделать
дальше (см. «Передача результатов»).

### Бюджет и безопасность запуска

- Перед запуском `all` скрипт печатает оценку стоимости и спрашивает подтверждение;
  флаг `--yes` пропускает вопрос. Целевой бюджет всего прогона — не больше $1.
- Таймауты на каждый запрос; один сбой не роняет весь прогон — ошибка пишется в результаты.
- Идентификаторы моделей и формат событий бери из официальной документации, прочитанной
  сейчас; ссылки — в комментариях кода.

### Передача результатов

Скрипт кладёт итог в `docs/research/00b-results.md` (копия `out/results.md` без путей к
звуку) и печатает команды для пользователя:

```
git add docs/research/00b-results.md && git commit -m "[S00b] Результаты проб" && git push
```

## Что ты можешь проверить сам

Без ключа: `--help`, разбор аргументов, чтение `credentials.properties` (на поддельном
файле во временном каталоге), нормализацию и сравнение текстов, разбиение групп — модульными
тестами (`pytest`). Сетевую часть — не можешь; так и напиши в отчёте.

## За пределами этапа

- любые изменения Kotlin-кода и `android_app/`;
- запуск проб с настоящим ключом;
- выводы о выборе синтеза — их сделает архитектор по `00b-results.md`.
