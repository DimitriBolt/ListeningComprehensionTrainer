## Зачем этап

Пользователь занимается, **не глядя на экран** (наушники, телефон в кармане). Сейчас он
не слышит, что разговор закончился или сломался, и ждёт ответа впустую
(`android_app/app/Issues.txt`). А когда разговор обрывается сам, нет журнала, по которому
можно найти причину. Эти две вещи нужны до миграции моделей (S02): без журнала сбои S02
будет нечем разбирать.

Модели и сетевые вызовы не меняются.

## Что сделать

### 1. Каждое состояние слышно

Звуковые сигналы — короткие, различимые на слух, не дольше 0,5 с, без речи (речь — S02).
Сигнал играет `AudioOutput`, решает когда — `ConversationController`.

| Событие | Сигнал | Сейчас |
|---|---|---|
| началась запись ученика (оба режима) | «говори» | только в авто-режиме |
| запись закончена, иду распознавать/думать | «обрабатываю» | есть |
| жду учителя дольше 5 с | тихий «тик» каждые 3 с, пока жду | нет |
| ученик ничего не сказал | «не услышал» | нет |
| ошибка (сеть, распознавание, микрофон) | «ошибка» — отчётливо отличается от остальных | нет |
| разговор окончен: Stop, прощание после 3 молчаний, ошибка, Back, остановка сервиса, конец ответа в ручном режиме | «конец» — нисходящий, «ждать нечего» | нет |

Если ошибка заканчивает круг — играются «ошибка», затем «конец».
Таблицу фактических сигналов (как звучит, когда играет) — в отчёт; архитектор перенесёт её
в `ARCHITECTURE.md`.

### 2. Журнал событий

- Файл в личном хранилище приложения (`filesDir/logs/`), с ротацией (например,
  2 файла по 1 МБ). Каждая строка: время с мс, источник, событие.
- Писать: каждый переход состояния контроллера с причиной; запуск/остановку сервиса,
  `onDestroy`, пересоздание Activity; потерю и возврат аудиофокуса; смену аудиовыхода
  (подключение и отключение Bluetooth); каждую ошибку с типом и стеком; длительность
  каждого сетевого вызова и код ответа; **причину каждого выхода из круга** — это
  главное; необработанные исключения (`Thread.setDefaultUncaughtExceptionHandler`)
  — записать и передать дальше.
- **Не писать:** ключ, тексты реплик ученика и учителя. Только длины текстов.
- Как пользователь достаёт журнал с телефона — одна команда в отчёте
  (для debug-сборки подойдёт `adb exec-out run-as com.example.listeningtrainer cat …`).
  Проверь, что команда работает.
- `LCT-Timing` из S01 тоже пишется в журнал.

### 3. Поворот экрана не прерывает разговор

`android_app/app/Issues.txt`: при повороте экрана во время разговора приложение
показывает начальный экран, и кажется, что разговор закончился. Причина, по коду:
`currentScreen` в `MainActivity` хранится в `remember`, а не переживает пересоздание
Activity, хотя разговор в сервисе продолжается. Исправить так, чтобы после поворота
был виден идущий разговор. Проверь, что разговор при этом не перезапускается.

### 4. История разговора переживает «Back»

Решение пользователя: после «Back» и повторного входа учитель помнит прежний разговор,
пока приложение не закрыто совсем. Звуковой сигнал «конец» на «Back» при этом играет.
Если удобнее — кнопка «New conversation» на экране разговора, чтобы начать с нуля.

### 5. Копии записей в `Music/ListeningTrainer`

Сейчас каждая реплика ученика копируется в общую папку `Music` (S01 «Замечено»), файлы
копятся. Оставить копирование **только в debug-сборке** и хранить только последние 20 файлов.

## Решения, которые не менять

- Кнопка «Stop» пока учитель говорит останавливает всё и выключает авто-режим, как
  сейчас (решение пользователя).

## За пределами этапа

- голосовые сообщения об ошибках и повтор запроса, таймауты (S02);
- громкость синтеза (S02 — после смены синтезатора);
- `delay(800)` после поиска (S02);
- новые модели и Realtime API (S02).

## Критерии приёмки

- [ ] все шесть событий из таблицы слышны; тесты контроллера проверяют, какой сигнал
      когда запрашивается (в том числе «конец» на каждом пути выхода из круга)
- [ ] журнал пишется, ротируется, не содержит ключа и текстов; команда выгрузки работает
- [ ] в журнале есть причина каждого выхода из круга
- [ ] поворот экрана во время разговора показывает разговор, сам разговор не прерывается
- [ ] история переживает «Back»
- [ ] копии записей — только в debug, не больше 20
- [ ] `assembleDebug`, `assembleRelease`, `testDebugUnitTest` проходят
- [ ] ручная проверка для пользователя включает: разговор с выключенным экраном и
      телефоном в кармане — по одним звукам понятно, что происходит; выключение Wi-Fi
      посреди разговора → «ошибка» + «конец»; поворот экрана; выгрузка журнала
- [ ] `docs/stages/01b-report.md` по шаблону; коммиты `[S01b]`, каждый сразу с push
