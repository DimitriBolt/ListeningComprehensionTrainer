## Зачем этап

**2027-01-06 OpenAI отключает `tts-1`, и учитель замолчит.** Отдельной модели синтеза
у OpenAI больше нет; замена — `gpt-realtime-2.1-mini` в роли читающего движка (решения
D8, D9). Пробы S00b: 50 из 50 групп прочитаны дословно, первый звук через 0,47 с.

Заодно этот этап убирает две причины медленного ответа из журнала S01b
(`docs/ARCHITECTURE.md`, «Эталон по журналу»): первая группа сейчас ждёт в общей очереди
из 20–80 параллельных запросов (медиана 1,8 с), а щит Bluetooth добавляет 1,2 с тишины,
хотя пользователь теперь в проводных наушниках.

Распознавание и учитель не меняются — это S02b.

## Что сделать

### 1. `RealtimeSynthesizer`

Новая реализация `Synthesizer` по решениям D8–D9:

- WebSocket к Realtime API, модель `gpt-realtime-2.1-mini`, голос `verse`, скорость 0.88,
  инструкции сессии — «Промпт 1» из `docs/research/00b-results.md` (там же протокол;
  работающий код на Python — `tools/probe/probe.py`, подкоманда `verbatim`).
- Каждая группа — отдельный ответ вне разговора (`conversation: "none"`), только звук.
- Сессия открывается заранее (при старте сервиса или в начале записи ученика), чтобы
  подключение (≈ 1 с в пробах) не попадало во время ответа. Держать одну сессию на разговор;
  переподключаться при обрыве; закрывать при остановке сервиса.
- Звук — PCM 24 кГц моно. `SpeechAudio` получает вариант для PCM (D9); `AudioOutput` играет
  его через `AudioTrack`. Начинать играть по первым кускам (`output_audio.delta`), не дожидаясь
  конца группы — если это не усложняет код сверх меры; иначе — по концу группы, и написать
  в отчёте, сколько это стоит по времени.
- Идентификаторы, голос, скорость, адрес — в `ModelConfig.kt`.
- Сверять расшифровку (`output_audio_transcript.done`) с текстом группы после нормализации,
  как в пробах. Расхождение → один повтор → если снова расхождение или ошибка, эта группа
  читается запасным синтезом (п. 2). Каждое расхождение и каждый переход на запасной синтез —
  в журнал (без текстов, только номер группы, тип и длины).

### 2. Запасной синтез — Android `TextToSpeech`

- Реализация `Synthesizer` на встроенном `TextToSpeech` (английский, скорость 0.88).
- Используется: для отдельной группы (п. 1); для всего ответа, если Realtime недоступен
  (нет сети до OpenAI, ошибка сессии, 401/429) — с записью причины в журнал.
- Если на телефоне нет английского голоса или движка — ошибка синтеза, как сейчас
  («ошибка» + «конец»), с понятной причиной в журнале.
- Голосовые сообщения об ошибках — не в этом этапе (S02b), но этот класс они будут
  использовать (D21) — сделай его пригодным для этого.

### 3. Группы по порядку, первая — первой

- Вместо «все группы сразу параллельно» — синтез по порядку с небольшим опережением:
  первая группа запрашивается первой и ничего не ждёт; дальше держать готовыми 2–3 группы
  вперёд. Число — в `ModelConfig.kt`.
- Паузы между группами — строго по эталону (`ARCHITECTURE.md`, «Эталон озвучки»).
- «Stop» и «← Back» обрывают и воспроизведение, и незаконченные запросы синтеза.

### 4. Щит Bluetooth только для Bluetooth (D17)

- Щит — локальная тишина (нули в `AudioTrack`), не синтезированные точки (D9).
- Тишина в начале нужна, только когда звук идёт в Bluetooth. Для проводных (`usb`, `wired`)
  и динамика — без тишины. Выход проверять перед каждым ответом; какой выход — в журнал.
- Расчёт «следующую группу начинать на N мс раньше» остаётся корректным в обоих случаях.

### 5. Громкость

`android_app/app/Issues.txt`: учитель «в разы тише YouTube и Spotify» на максимуме.

- Измерь в журнале громкость звука учителя (RMS и пик в дБFS на группу) — у Realtime и у
  запасного синтеза.
- Приведи громкость к целевой: RMS около −16 дБFS с ограничением пика (без перегрузки и
  щелчков). Значения — в `ModelConfig.kt`.
- Громкость сигналов (`CueTones.LOUD`, `QUIET`) подстрой так, чтобы сигналы были чуть тише
  голоса учителя, а не громче.
- Поток воспроизведения — `USAGE_MEDIA`, чтобы громкость управлялась обычными кнопками
  громкости как у музыки. Если сейчас иначе — напиши, что было.

### 6. Журнал

- Каждый сыгранный сигнал — строка в журнал (`[Audio] cue: END` и т. п.). В S01b пользователь
  не мог подтвердить сигналы на слух, журнал должен показывать их сам.
- По каждой группе: каким синтезом, время до первого звука, длительность, громкость.
- `[Timing]`: добавить момент, когда голос учителя **слышен** (после щита, если он есть).
- `onTrimMemory` писать только при смене уровня (сейчас сотни строк шума).

### 7. Мелочи

- `allowBackup="false"` в манифесте (D20).
- `TtsSynthesizer` (`tts-1`) и `MediaPlayerOutput` удалить, если больше не используются.
  Оставлять `tts-1` «на всякий случай» не нужно — запасной синтез есть.

- потоковый ответ учителя (S02c);

## Критерии приёмки

- [ ] учитель говорит голосом `verse` через Realtime; `tts-1` в коде больше нет
- [ ] расхождение с текстом → повтор → запасной синтез; всё в журнале
- [ ] без сети до OpenAI ответ читается запасным синтезом (проверка: заблокировать
      `api.openai.com` после того, как ответ учителя уже получен — например, подставным
      синтезатором в тесте и на эмуляторе)
- [ ] первая группа синтезируется первой, опережение 2–3 группы
- [ ] щита нет на проводных наушниках, есть на Bluetooth
- [ ] громкость нормализована; в журнале RMS и пик по группам
- [ ] каждый сигнал — строка в журнале
- [ ] модульные тесты: нормализация громкости, сверка текста, порядок и опережение синтеза,
      переход на запасной синтез, щит по типу выхода
- [ ] `assembleDebug`, `assembleRelease`, `testDebugUnitTest` проходят
- [ ] ручная проверка для пользователя (простыми словами, см. `STAGE_RULES.md`): обычный

      «Stop» посреди ответа; режим полёта после того, как учитель начал отвечать;
      выгрузка журнала
- [ ] в отчёте: медиана и худший случай «конец записи → голос слышен» по журналу
      пользователя — сделает архитектор; ты дай формулу и строки, по которым считать
