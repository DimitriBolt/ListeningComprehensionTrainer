## Зачем этап

S02 должен заменить три модели до 2027-01-06. Сейчас всё перемешано в
`TrainerViewModel.getTeacherReply` и `MainActivity`, и любая замена — правка в десяти местах.
Этот этап раскладывает код по компонентам из `docs/ARCHITECTURE.md` («Целевая структура»),
**не меняя модели и поведение** (кроме перечисленных ниже исправлений). После него S02
пишет новые реализации интерфейсов и не трогает остальное.

Пользователь подтвердил: нынешнее приложение работает хорошо, ≈ 3 с до первого звука.
Главный риск этапа — сломать то, что работает. Делай маленькими шагами, каждый коммит
собирается.

## Что сделать

### 1. Компоненты и интерфейсы

Пакеты на твой выбор, но с ясными границами. Интерфейсы и нынешние реализации:

| Интерфейс | Нынешняя реализация (обёртка над существующим кодом) |
|---|---|
| `AudioInput` | `AudioRecorder` (пока WAV-файл, 44,1 кГц как сейчас — частоту не меняем) |
| `TurnDetector` | нынешнее правило: порог 59 дБ, 3 с тишины |
| `Transcriber` | `whisper-1` |
| `Tutor` | `gpt-4o-mini` + `get_weather` + `search_live_web`, история, системный промпт |
| `SpeechPlanner` | `splitIntoChunks` (см. раздел 3) |
| `Synthesizer` | `tts-1`, голос `nova`, параллельные запросы как сейчас |
| `AudioOutput` | `MediaPlayer`, щит Bluetooth как сейчас |

Учти на будущее, но **не реализуй**: в S02 `Synthesizer` будет отдавать поток PCM 24 кГц
(Realtime API), а не файл MP3. Интерфейс должен это допускать без переделки контроллера —
например, синтезатор возвращает «звук группы» абстрактно, а `AudioOutput` умеет его играть.
Опиши выбранную форму в отчёте.

`SpeechToTextManager.kt` (системный распознаватель Android) не используется в цикле
диалога — проверь; если так, удали.

### 2. `ConversationController` в сервисе

- Цикл `Idle → Listening → Thinking → Speaking → Listening …` и `Error` — машина состояний
  в чистом Kotlin (без Android-классов), с модульными тестами переходов: обычный круг,
  тишина 3 раза подряд → прощание и выход из авто-режима, ошибка сети, остановка
  пользователем посреди речи.
- Контроллер живёт в `TrainerService` (foreground, тип microphone). Запись в авто-режиме
  запускает **контроллер**, а не `LaunchedEffect` в `MainActivity`. Это исправляет сбой
  «в фоне учитель не ждёт ответа, а сразу говорит снова».
- UI только показывает состояние (статус, текст ученика, текст учителя, текущая группа)
  и шлёт команды (начать, стоп, авто-режим). Способ связи UI с сервисом — на твой выбор,
  попроще.
- Звуковые сигналы (обработка, «твоя очередь») — как сейчас.

### 3. `SpeechPlanner` и три исправления

Перенеси `splitIntoChunks` в отдельный класс без Android-зависимостей и покрой тестами.
Сначала тесты фиксируют **нынешнее** поведение, затем отдельными коммитами исправь три
ошибки, найденные в S00b (`docs/stages/00b-report.md`, «Замечено»):

1. `1. **Заголовок**` должен быть одной группой (эталон в `ARCHITECTURE.md`). Сейчас
   получается `1.` | `**Make**`.
2. Разрез «перед союзом» должен срабатывать только перед целым словом: `sorry`, `ask`,
   `whole`, `afternoon`, `order`, `some` не режутся.
3. Служебные метки `(Live Web Data):` и `(Search attempted, fallback):` не озвучиваются.
   Пользователь подтвердил, что сейчас они звучат вслух. На экране метку оставить можно.

Остальные недостатки разбиения (обрыв внутри кавычек, деление пополам) **не трогай** —
это этап S06. Паузы и предел 6 слов — строго по эталону.

### 4. Модели и адреса — в одном файле

Все идентификаторы моделей, голос, скорость, адреса API, таймауты — в одном файле
конфигурации (например, `ModelConfig.kt`). Значения прежние.

### 5. Замер скорости

На каждом круге писать в Logcat с тегом `LCT-Timing` одну строку: время от конца записи
ученика до (а) готового текста, (б) ответа учителя, (в) первого звука учителя, в мс.
Ключ и тексты реплик в лог не писать. В отчёт — команда, которой пользователь это читает
(`adb logcat -s LCT-Timing`).

### 6. Ключ в отладочной сборке

- В **debug**-сборке Gradle читает `APIkey` из `credentials.properties` в корне репозитория
  (на уровень выше `android_app/`) и кладёт его в `BuildConfig`. Если файла нет — пустая строка,
  сборка не падает.
- В **release** ключ в сборку не попадает никогда.
- Приложение берёт ключ из `BuildConfig`, только если сохранённого ключа нет.
- Ключ не логируется и не показывается. Не печатай и не читай содержимое файла сам:
  у тебя его нет, у пользователя — есть.
