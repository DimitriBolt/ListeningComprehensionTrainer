### 1. `ResponsesTutor` (D36)
(`openai/ResponsesTutor.kt`, `openai/ResponsesTransport.kt`, `config/ModelConfig.kt`)

- **Запрос:** `POST /v1/responses`.
  - Параметры: `gpt-6-luna`, `reasoning.effort: none`, `stream: true`, `store: false`.
  - Инструменты: `tools: [{type: web_search, search_context_size: low}]`.
  - `include: [web_search_call.action.sources]` — без него не узнать типы источников для журнала.
  - Модель, адрес, `low`, окно истории и цены лежат в `ModelConfig.kt`.
  - Формат событий и полей сверен с документацией OpenAI, прочитанной сейчас (ссылки в начале
    `ResponsesTutor.kt`).
- **Поток.** Читается прямо через OkHttp, построчно (SSE), новых зависимостей нет.
  - `OkHttpResponsesTransport` читает поток, `ResponsesTutor` разбирает события. Транспорт — интерфейс,
    в тестах его подменяют.
  - «Stop» обрывает HTTP-вызов сразу.
  - Общий предел на весь поток прежний: `TUTOR_CALL_TIMEOUT_MS` = 20 с (худшее в пробе — 12,3 с).
- **История.**
  - В истории только реплики ученика и ответы учителя. Ответ хранится вычищенным, без сносок.
  - Пара «реплика — ответ» попадает в историю только после `response.completed`. Оборванный ответ
    не запоминается (решение пользователя), а повтор запроса не удваивает реплику.
  - `trimHistory` теперь просто `takeLast(30)`: пар «вызов инструмента — ответ» больше нет.
- **Системный промпт** (согласован с пользователем):
  - искать только ради свежих фактов: цены, новости, погода, спорт, расписания, часы работы,
    время событий, кто сейчас на должности;
  - не искать ради разговора, грамматики, значения слов и общих знаний;
  - если искал — назвать конкретные данные;
  - если поиск ничего не дал — честно сказать (правило S02b, формулировка из пробы S02c);
  - дата осталась;
  - строки «Your memory is limited to 2023» больше нет;
  - пункты про короткие фразы и исправление ошибок — слово в слово прежние.
- **Удалено:**
  - код: `ChatTutor`, `WebTools`, `ToolResults`, `get_weather`, разбор DuckDuckGo, обращения к wttr.in;
  - Chat Completions: `ChatRequest`/`Message`/`Tool…` в `OpenAiService` и `tutorApi`;
  - настройки: `toolsHttp`, `TOOLS_CALL_TIMEOUT_MS`, `WEATHER_URL`, `SEARCH_URL`, `SEARCH_USER_AGENT`;
  - метки `(Live Web Data):` и `(Search attempted, fallback):` в `SpeechPlanner` и `TranscriptionPrompt`
    (мёртвый код; нарезку обычного текста это не меняет).

**Новый интерфейс `Tutor`** (`conversation/Components.kt`):

```kotlin
interface Tutor {
    suspend fun reply(studentText: String, onEvent: suspend (TutorEvent) -> Unit)
    suspend fun farewell(onEvent: suspend (TutorEvent) -> Unit)
    val lastTeacherText: String?   // последний ответ без сносок
    fun newConversation()
}
sealed interface TutorEvent {
    data class Text(val delta: String)          // кусок текста (сноски могут прийти в тексте)
    data object SearchStarted                    // начался поиск
    data object SearchFinished                   // поиск кончился
    data class Source(val source: TutorSource)   // источник для экрана (title, url), каждый адрес — один раз
    data class Done(val stats: TutorStats)       // конец: токены, поиски, типы источников, цена
}
```

- `onEvent` вызывается по порядку, в контексте вызывающего.
- Сбой — `ServiceException` с типом сбоя. Сам учитель запрос **не повторяет**: повторять ли, решает
  контроллер, потому что это зависит от того, прозвучало ли уже что-нибудь.
- Классы `TutorReply` больше нет.

**Повтор и обрыв** (`ConversationController.answer`):
- **Ничего ещё не прозвучало** (даже если текст уже пошёл и группы ушли в синтез):
  - всё бросается, экран очищается;
  - через 1 с — один повтор, если тип сбоя это допускает: сеть, таймаут, 5xx, 429;
  - `insufficient_quota`, 401 и 400 не повторяются;
  - повтор не удался — «ошибка», фраза голосом телефона, «конец».
- **Учитель уже говорит:** дочитываются группы, уже отданные в синтез, затем «ошибка», фраза голосом
  телефона и «конец» (`TUTOR_ERROR`).
- Фраза «Let me check.» звуком ответа не считается: после неё повтор ещё возможен.

### 3. Потоковая нарезка (D38)
- `StreamingSpeechPlanner` — обёртка над `SpeechPlanner` по правилу из `02c-results.md`. Сам `SpeechPlanner`
  не менялся (кроме удаления мёртвых меток).
- **Поправка правила:** жирный `**…**` не режется посередине. Точка внутри пары — не точка; незакрытая
  `**` на последней строке — граница. Пары ищутся так же, как их видит `SpeechPlanner`: в пределах
  строки, слева направо.
  - Все 5 расхождений пробы были отсюда. Заголовок вроде `**Monday, November 23, 2026**` резался после
    «Monday, », и префикс без закрывающей `**` давал группе перед ним 600 мс вместо 1600.
  - Тексты групп в пробе совпадали; расходились только паузы.
- **Пауза после группы — поздно.** Группа уходит в синтез с текстом. Паузу контроллер спрашивает у
  обёртки (`pauseAfter(i)`), когда группа прозвучала и пришла следующая или ответ кончился. Пауза
  берётся из самой свежей нарезки. Даже если правило где-то промахнётся, пауза будет верной, если к этому
  моменту продолжение уже пришло.
- **Расхождения.** Если текст уже отданной группы разошёлся с новой нарезкой — строка в журнал.
  Отданное не переотдаётся, нарезка идёт дальше.
- **Тест:** все 90 ответов из приложения `02c-results.md` (вынесены в тестовый ресурс `02c-replies.txt`),
  каждый нарезан 18 способами — по 1, 2, 3, 5, 8, 13, 40 знаков, целиком и 10 случайных. Каждый раз те
  же тексты групп **и паузы**, что у готового текста. Паузы проверяются так, как их берёт контроллер:
  в момент прихода следующей группы. Расхождений 0.
- **`SpeechPipeline`** получает группы каналом (`ReceiveChannel<SpeechChunk>`), а не списком. Опережение 3
  и порядок прежние. В журнале номер группы теперь без общего числа: `group 3`, а не `group 3/12` —
  общее число заранее неизвестно.
- **Текст на экране** растёт по мере ответа.
- **Python-копия** `tools/probe/speech_planner.py` поправлена так же: правило жирного и `pause_after`.
  Добавлены тесты на тех же 90 ответах.

### 4. Фраза на время поиска (D39)
- **Фраза:** одна, «Let me check.» (выбор пользователя), константа `ConversationController.SEARCH_FILLER`.
- **Синтез:** через Realtime, один раз за жизнь сервиса, пока ученик говорит первую реплику. Со сверкой
  расшифровки и той же громкостью. Не вышло — попытка на следующей реплике.
- **Когда звучит:** поток сообщил о начале поиска, а учитель ещё ничего не сказал (ни одна группа не
  ушла в синтез). Фраза ещё не готова — пропускается.
- Фраза не обрывается: первая группа ответа ждёт её конца. «Тик» ожидания — как раньше.

### 5. Журнал и замер

`[Timing]` (одна строка на ответ, пишется **в конце ответа**: `tutor` — это конец потока):

```
enc=0 stt=812 first_token=3410 first_group=3655 tutor=4120 search=yes search_ms=1900 filler=yes reply_chars=180 first_audio=4300 audible=4300
```

Поля:
- `first_token` — первый кусок текста учителя;
- `first_group` — первая группа ушла в синтез;
- `tutor` — конец ответа;
- `search` — искал ли учитель;
- `search_ms` — от начала первого поиска до конца последнего;
- `filler` — звучала ли фраза;
- `reply_chars` — длина ответа без сносок.

Все времена считаются от конца записи, как раньше. `first_audio` и `audible` — первая группа **ответа**,
а не фраза.

Остальные строки:
- **По каждому ответу:**
  `[Network] tutor reply: tokens in 812 (cached 512), out 64; searches 1; sources oai-weather×1, url×5; cost $0.0101`
  - цена — по прайсу из пробы ($0.10 / $0.01 / $0.50 за 1M и $0.01 за поиск);
  - поисков считается столько, сколько было действий `search` (именно они платные);
  - без текстов, запросов и адресов.
- **Ответ:** `[Controller] reply: N chars, M groups`; при обрыве — `reply broken off: M groups sent to synthesis`.
- **Расхождение нарезки:** `[Controller] stream planning: text of sent groups 3 changed later`.
- **Фраза:**
  - `search filler ready: N ms of audio`;
  - `search started, nothing said yet: filler phrase`;
  - `search started: filler not ready, skipped`.
- **Повтор и обрыв:**
  - `tutor failed (…), nothing spoken yet: retry in 1000 ms`;
  - `tutor retry succeeded`;
  - `tutor retry failed (…)`;
  - `tutor failed (…), no retry`;
  - `tutor stream broke (…) while the teacher was speaking: ready groups spoken`;
  - сам учитель пишет `[Network] tutor stream: failed (…)`.

## Отклонения от брифа
- **Правило безопасной точки поправлено** (жирный не режется посередине). Без этого поздняя пауза
  спасала бы только при быстром продолжении. С поправкой паузы верны уже в момент отдачи: тест на 90 ответах.
- **Из `[Timing]` убран `llm1`** (время первого запроса). Второго запроса больше нет, его место занял
  `first_token`.
- **Строка `[Timing]` пишется в конце ответа**, а не в момент первого звука: иначе `tutor` (конец потока)
  ещё неизвестен. Пишется и при сбое учителя, если ответ начинался (поля, которых не было, — `-`).
- **Повтор перенесён из учителя в контроллер.** Правило «повтор, только если ничего не прозвучало» знает
  только контроллер. `withRetry` по-прежнему используется в распознавании.
- **`response.incomplete`** (например, предел токенов) считается законченным ответом. В журнале строка
  `tutor reply incomplete (причина)`; ответ звучит и запоминается.
- **Выход звука** (`prepareReply`) проверяется перед запросом к учителю, а не после ответа: ответ
  начинает звучать раньше, чем кончается. По-прежнему один раз на ответ.

## Ручная проверка для пользователя
Подготовка: собрать и установить debug-сборку (ключ берётся из `credentials.properties`), надеть
проводные наушники. Телефон можно держать в кармане, кроме шагов 6 и 7. Начинать каждый вопрос средней
кнопкой гарнитуры или «Talk to Teacher 🎙️», заканчивать средней кнопкой или паузой.

1. **(обязательно) Обычный разговор.** Скажите «I went to the park yesterday. It was very nice.» →
   учитель отвечает как обычно, без «Let me check.». Голос начинается быстро, паузы между кусочками
   фразы прежние.
2. **(обязательно) Цена бензина.** Скажите «How much is gas in Tucson today?» → учитель сразу говорит
   **«Let me check.»**, потом может быть тишина или «тик». Затем он **называет цену в долларах** и
   задаёт вопрос. Ни адресов сайтов, ни слов вроде «what's the price of gas dot com» не слышно.
3. **(обязательно) Погода.** Скажите «What's the weather in Tucson now?» → «Let me check.», затем
   температура и погода.
4. **(обязательно) Новость.** Скажите «What is the latest news about SpaceX?» → «Let me check.», затем
   конкретная новость с датой. Названий сайтов вслух нет.
5. **(обязательно) Длинный ответ.** Скажите «Please explain the difference between "make" and "do" with
   examples.» → голос начинается заметно раньше, чем раньше на таких длинных ответах. Ответ звучит до
   конца без провалов, паузы перед новыми абзацами и пунктами длиннее, чем внутри фраз.
6. **(обязательно) Режим полёта посреди ответа.** Снова задайте длинный вопрос, как в шаге 5. Как только
   **зазвучал голос учителя**, включите режим полёта → учитель договаривает то, что успел подготовить,
   затем две низкие жужжащие ноты, голос телефона говорит «I can't connect to the internet…» (или
   «The server is not answering…»), затем три ноты вниз. Если учитель договорил ответ до конца без
   ошибки, значит, ответ успел прийти целиком: это тоже правильно, журнал покажет. Выключите режим
   полёта.
7. **(обязательно) Источники на экране.** После шага 2 или 4 посмотрите на экран: под ответом учителя
   строка «Sources:» и подчёркнутые заголовки. Нажмите на заголовок → открывается страница сайта в
   браузере. Вернитесь в приложение.
8. (желательно) **Режим полёта до ответа.** Включите режим полёта, задайте вопрос → примерно через
   секунду-две две низкие ноты, голос телефона «I can't connect to the internet…», три ноты вниз.
   Выключите режим полёта.
9. **(обязательно) Журнал.** Запустите `tools/pull-log.sh` и пришлите файл в чат архитектора.

Что архитектор проверит по журналу (пользователю смотреть не нужно):
- **`[Timing]`:** `first_token`, `first_group`, `tutor`, `search=yes|no`, `search_ms`, `filler`,
  `audible`; цель — медиана `audible` с поиском ≤ 6 с, без поиска ≤ 4 с;
- **запросы:** `[Network] POST api.openai.com/v1/responses -> 200 in N ms`; запросов к
  `duckduckgo.com` и `wttr.in` больше нет;
- **цена:** `[Network] tutor reply: tokens …; searches N; sources …; cost $…` — типы источников
  (`oai-weather` и т. п.) и цена каждого ответа;
- **фраза:** `[Controller] search filler ready: …` один раз за жизнь сервиса; `search started, nothing
  said yet: filler phrase` на вопросах с поиском;
- **нарезка:** строк `stream planning: …` быть не должно;
- **шаг 6:** `reply broken off: …`, `tutor stream broke (…) while the teacher was speaking: ready groups
  spoken`, `circle end: TUTOR_ERROR (tutor error, no_network)` или `timeout`;
- **шаг 8:** `tutor failed (…), nothing spoken yet: retry in 1000 ms`, затем `tutor retry failed (…)`.
