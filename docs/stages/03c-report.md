# Отчёт S03c — Конец реплики в шуме: Silero

## Сделано

### 1. Silero VAD в приложении (D64, D66)

**Подключение**
- `com.microsoft.onnxruntime:onnxruntime-android:1.32.0` — последняя версия на Maven Central (проверено 2026-11-26), та же,
  что в пробе. `android-vad` не используется.
- Модель `assets/silero_vad.onnx` — из колеса `silero-vad` 6.3, как в пробе (2 204 103 байта, sha256 `f6f4407b…09b31`).
- Лицензия MIT лежит рядом: `assets/silero_vad.LICENSE.txt`. onnxruntime — тоже MIT (лицензия внутри AAR).
- ABI: только `arm64-v8a` (`ndk.abiFilters`), в debug и в release.
  - x86_64 не нужен: тесты идут на JVM с `com.microsoft.onnxruntime:onnxruntime:1.32.0` (`testImplementation`; Android-сборка
    из тестового classpath исключена).

**Вес APK**

| | до | после | разница |
|---|---|---|---|
| debug | 12,67 МБ | 51,17 МБ | +38,5 МБ |
| release (без подписи) | 10,05 МБ | 48,53 МБ | +38,5 МБ |

Внутри: `libonnxruntime.so` 36,3 МБ, `libonnxruntime4j_jni.so` 0,1 МБ, модель 2,2 МБ.

Почему больше оценки D66 (≈ +14 МБ):
- при `minSdk 24` сборка кладёт `.so` в APK **несжатыми**, и телефон грузит их прямо из APK;
- с `packaging.jniLibs.useLegacyPackaging = true` APK меньше (debug 29,9 МБ, +17,2), но при установке библиотеки
  распаковываются: на телефоне ≈ 66 МБ против ≈ 51 МБ сейчас.

Оставил как есть. Это отклонение — см. ниже и вопрос 2.

**Устройство**
- **`VadTurnDetector`** (`conversation/`, чистый Kotlin) — решает «речь / тишина / конец» по вероятностям кадров:
  - звук приходит кусками любой длины и режется на кадры по 512 отсчётов;
  - время — по звуку (номер кадра), а не по часам;
  - кусок обрабатывается целиком, момент конца — в `endMs`;
  - копит речь и время вывода на кадр: кадров, среднее и максимальное.
- **`SpeechProbability`** — интерфейс источника вероятности.
  - Реализация — `audio/SileroVad.kt` на onnxruntime: 16 кГц, кадр 512 + 64 отсчёта контекста, состояние 2×1×128
    между кадрами, `reset()` в начале каждой реплики. Это ровно обёртка `OnnxWrapper` из silero-vad и проба S03b.
  - В тестах — подделки.
- **`SileroModel`** — один сеанс onnxruntime на процесс (`TrainerApplication.vadModel`).
  - Создаётся при первой записи, в её потоке.
  - Не закрывается, пока жив процесс: так он не закроется посреди вывода.
  - У каждого `SileroVad` своё состояние.
- **`TurnDetector`** теперь получает звук: `onAudio(pcm, count): TurnEnd?` (`SILENCE` / `LIMIT`) вместо
  `onLevel(db, nowMs)`. Есть `heardSpeech` и `stats`.
  - Громкость (пик в журнале, уровень на экране и в режиме записи) считается как раньше: окнами 80 мс.
- **Вывод — не в главном потоке:** `AudioRecorder.record` идёт в `Dispatchers.IO`, кадры считаются там же после
  каждого чтения микрофона.

**Правила** (`ModelConfig.kt`)

| Правило | Значение |
|---|---|
| `VAD_SPEECH_PROB` | 0,5 — речь при p ≥ 0,5 |
| `TURN_END_SILENCE_MS` | 3000 мс без речи после последнего кадра речи; при молчании с начала — от начала записи |
| `TURN_MIN_SPEECH_MS` | 200 мс — порог `heardSpeech` |
| `RECORD_MAX_MS` | 90 000 — предохранитель, теперь в детекторе (D31) |

- Порог `heardSpeech` подобран по записям S03b: в записях без речи набиралось ≤ 128 мс (0, 0, 32, 0, 128, 32, 0, 0),
  в самой короткой реплике — 608 мс. 200 мс разделяет их с запасом.
- Кнопка гарнитуры и «Stop Recording» по-прежнему кончают запись сразу (`finish()`, D29).
- Кадр 32 мс, поэтому конец наступает на кадре 94: через 3008 мс тишины, предел — на 90 016 мс.

**Маска после пульса убрана (D68).**
- `PulseEchoGate` и `RecordingMeter` удалены, `LISTEN_PULSE_MIC_MASK_MS` тоже.
- Осталась только отметка начала пульса `PulseMarks`: режим записи пишет моменты в JSON. Сам пульс не менялся.

**Удалены `SilenceTurnDetector` и его тест.** Порог 59 дБ / 3 с остался только как эмуляция в режиме записи.
Индикатор «Noise: N dB» на экране больше не выделяется цветом выше 59 дБ: порога в приложении нет.

### 3. Журнал
- Строка записи:
  `recording: N ms, speech N ms (silero), ended by silence | button | limit, peak N dB, vad frames N, avg N.N ms, max N.N ms, pulses: N`.
  - Число пульсов осталось в конце строки, как было.
  - `vad frames`, `avg` и `max` — время вывода одной записи. Это и есть замер на телефоне: строка пишется на каждую
    реплику.
- Решение «молчание» — по `heardSpeech` детектора:
  `counted as silence: yes (speech under 200 ms, transcription skipped)`.

### 4. Режим записи (D69)
- В JSON (схема 2) рядом с `silenceDetector` (эмуляция 59 дБ / 3 с) — `sileroDetector`:
  - настройки приложения;
  - `endMs` — где кончил бы запись Silero (или `null`);
  - `heardSpeech` и `speechMs` к его концу;
  - кадров, среднее и максимальное время вывода за запись.
- Детектор запись по-прежнему не останавливает. Предохранитель 90 с — теперь через детектор.
- Своё состояние модели — отдельный `SileroVad` на том же сеансе.
- Поле `pulseMaskMs` убрано (маски нет). Проба его не читает.
- Строка журнала: `endpoint recording saved: …, pulses N, silero end N ms | none, …`.

## Отклонения от брифа
- **«Нет конца» 3 из 40 вместо 0 — цель недостижима при тишине 3000 мс.**
  - Все три записи — в тихой комнате (реплики 3, 4, 5). Пользователь нажал кнопку через 2,09 / 2,30 / 1,49 с после
    конца речи: раньше, чем пройдут 3 с тишины.
  - Проба S03b тишину 3000 мс для Silero не проверяла (её сетка — до 2000 мс). Её собственный автомат при 0,5 / 3000 мс
    даёт те же 3 (`silero_app_check.py`, справка). Цифра «0 из 40» в D64 и брифе, видимо, перенесена с более короткой
    тишины.
  - Тест проверяет то, что достижимо: «нет конца» только там, где кнопка нажата раньше 3,1 с после речи; в воде и на
    улице — ни одного.
- **Вес APK +38,5 МБ, а не ≈ +14 МБ** (D66): `.so` в APK несжатые (поведение сборки при `minSdk ≥ 23`). Так меньше
  места на телефоне. Сжатая упаковка — одна строка в `build.gradle.kts`, если нужен меньший файл APK.
- **Конец — на кадре, когда тишины ≥ 3000 мс**, то есть через 3008 мс (кадр 32 мс). Предохранитель 90 с — на кадре
  2813 (90 016 мс; в режиме записи файл 90 080 мс, конец 80-миллисекундного куска).
- **`TurnDetector` получает куски звука любой длины, а не ровно кадр.** Режет на кадры по 512 сам детектор: чистый
  Kotlin, покрыт тестами. `AudioRecorder` читает микрофон окнами 80 мс, как раньше.
- **Правило — строго по брифу.** Речь — кадр с p ≥ 0,5, тишина — всё остальное. Гистерезиса 0,15 и отбрасывания
  отрезков < 250 мс, как в автомате пробы S03b, нет. Python-сверка гоняет то же правило (`app_rule`). Автомат пробы на
  этих записях даёт те же «нет конца», ложную речь и ложный конец, задержку 3,16 с вместо 3,11.

## Ручная проверка для пользователя
1. **(обязательно)** Сборка с нуля: `./gradlew clean installDebug` (или «Build → Clean Project», затем «Run»).
   Приложение запускается.
2. **(обязательно) Тихая комната.**
   - Нажмите «Talk to Teacher 🎙️» (или среднюю кнопку гарнитуры) → «говори», потом тихое «тук» каждые 2 с.
   - Скажите короткую фразу («I like coffee.») и молчите → примерно через 3 с «обрабатываю», учитель отвечает.
     Всё как раньше.
3. **(обязательно) Вода.** Откройте кран рядом и повторите шаг 2 → примерно через 3 с после конца фразы «обрабатываю»,
   хотя вода шумит. Раньше запись в шуме не кончалась.
4. **(обязательно) Улица** (или громкий фон: машины, вентилятор) — так же: «обрабатываю» примерно через 3 с после фразы.
5. **(обязательно) Молчание с начала.** «Talk to Teacher 🎙️» и молчите (можно при шуме воды) → примерно через 3 с
   сигнал «ничего не услышал». Учитель не отвечает.
6. (желательно) **Кнопка.** «Talk to Teacher 🎙️», скажите фразу и сразу нажмите среднюю кнопку гарнитуры →
   «обрабатываю» сразу, без ожидания 3 с.
7. (желательно) **Режим записи.**
   - На экране практики нажмите «🎙 Endpoint recordings (debug)», затем «Water (kitchen tap nearby)».
   - Запишите одну реплику: средняя кнопка — «говори», скажите фразу, дождитесь двух «тук», средняя кнопка →
     «обрабатываю», на экране следующая реплика.
   - Затем «← Conditions» и «← Close».
8. Пауза посреди мысли дольше 3 с по-прежнему может закончить запись раньше времени. Это известно (D65) и
   решается в S04. Проверять не нужно.
9. **(обязательно)** Запустите `tools/pull-log.sh` и пришлите файл в чат архитектора.

Что архитектор проверит по журналу:
- `[Controller] recording: … speech N ms (silero), ended by silence, … vad frames N, avg N ms, max N ms` на шагах 2–4;
- `ended by button` на шаге 6;
- `counted as silence: yes (speech under 200 ms, …)` на шаге 5;
- `[Debug] endpoint recording saved: …, silero end N ms` на шаге 7.

## Вопросы к архитектору
1. **«Нет конца» 3 из 40** — все в тихой комнате, кнопка нажата через 1,5–2,3 с после речи. Принять, что цель «0» при
   3000 мс на этих записях недостижима? Вода и улица — 0, а это и была жалоба.
2. **Вес APK:** 51 МБ (несжатые `.so`, на телефоне ≈ 51 МБ) или сжатые (`useLegacyPackaging`: APK 30 МБ, на телефоне
   ≈ 66 МБ)? Сейчас — первое.
3. **Время вывода на телефоне** придёт в журнале ручной проверки. Если `max` будет больше ≈ 30 мс (кадр — 32 мс),
   стоит вынести вывод в отдельный поток. Сейчас он в потоке записи, буфер микрофона — 320 мс.
