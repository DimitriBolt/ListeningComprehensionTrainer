# Отчёт S03b — Конец реплики в шуме: записи и проба

## Сделано

### 1. Режим записи для пробы (только debug)
(`endpoint/EndpointScenario.kt`, `EndpointTake.kt`, `RecordingStore.kt`, `EndpointRecorder.kt`; `TrainerService`, `MainActivity`)

- **Вход:** на экране практики, в простое, кнопка **«🎙 Endpoint recordings (debug)»**. Есть только при `BuildConfig.DEBUG`
  (`EndpointRecorder.available`, тест). В release нет ни кнопки, ни объекта режима в сервисе: команды пропускаются.
  Открыть режим, пока идёт разговор, нельзя (строка `[Service] endpoint recording mode not opened: conversation is running`).
- **Условие** — список из 4: Silence, Water, Street, Steady noise. Затем реплики по одной: номер, текст крупно, указание,
  «Previous / Next», какие реплики уже записаны. Открывается первая незаписанная реплика.
- **Запись:**
  - начинает и кончает средняя кнопка гарнитуры (пока режим открыт, кнопка его) или кнопка на экране;
  - сигналы — «говори», пульс каждые 2 с (D28), «обрабатываю» после сохранения;
  - детектор запись **не** останавливает (`LevelTrace`: всегда `false`); кончают кнопка или предохранитель 90 с.
- **Сохраняется:** `filesDir/recordings/ep_<мс>_<условие>_<NN>.wav` + `.json`.
  - Звук — WAV 16 кГц моно без маски D34 и без сжатия: отдельный `AudioRecorder` с `pulseGate = null`, `compress = false`.
  - JSON:
    - условие, номер, вид и текст реплики, номер дубля;
    - время начала и длительность;
    - чем кончилась запись; отпускание и нажатие кнопки;
    - моменты пульсов — когда проигрыватель запустил звук (`PulseEchoGate.onPulse`);
    - уровень по окнам 80 мс и время чтения каждого окна;
    - где кончил бы запись нынешний детектор (59 дБ / 3 с);
    - телефон.
  - Хранятся последние 200 записей (WAV и JSON удаляются парой).
- **Журнал** (источник `Debug`), без текста реплик:
  `endpoint recording start (water #5, headset button)`,
  `endpoint recording saved: ep_…_water_05, take 1, 13440 ms, ended by button, pulses 6, old recordings deleted 0`.
- **`tools/pull-recordings.sh`** скачивает записи (`run-as`) в `diagnostics/recordings/`, печатает «реплик N из 12» по
  условиям и собирает архив `diagnostics/recordings-<дата>.tar.gz` для чата. Каталог `diagnostics/` в `.gitignore`
  (проверено `git check-ignore`).

### 3. Проба `python tools/probe/probe.py endpoint` (`tools/probe/endpoint.py`)
Итог — `docs/research/03b-endpoint.md` (+ `.json`). Там только числа, тексты сценария и распознанные тексты этих реплик,
звука нет.

- **Разметка конца речи.** Метки `whisper-1` (`verbose_json`, word) задают окно поиска. Сам конец берётся по энергии в
  полосе 300–3400 Гц.
  - Почему так: метки whisper ненадёжны. «noon» стоит на 1,4 с позже речи; в длинной паузе соседние слова растянуты на
    всю паузу.
  - Паузы посреди мысли тоже меряются по звуку.
  - **Ручная сверка 10 записей** по графикам волны и энергии: конец совпадает с волной (≈ 0,1 с) во всех 10. Список — в
    отчёте пробы.
- **Детекторы:**
  1. Порог громкости: эмуляция `SilenceTurnDetector`, 59 дБ / 3 с с маской и без, плюс 56, 62, 65 дБ и 1,5 с.
  2. Silero VAD v6.3 (ONNX, MIT): порог 0,3 / 0,5 / 0,7 × тишина 600–2000 мс × с маской после пульса и без.
  3. `server_vad` 500 / 700 / 1000 / 1250 / 1500 мс.
  4. `semantic_vad` low / medium / high / auto.
  5. Сверх брифа:
     - WebRTC VAD, режимы 1–3;
     - `gpt-live-transcribe` — новая модель потокового распознавания из документации OpenAI (прочитана 2026-11-26). Она
       **не поддерживает** `server_vad` / `semantic_vad`: конец решает детектор на устройстве, затем `commit`.
- **Текст:** нынешний путь (m4a 32 кбит/с в `gpt-transcribe`), сессия `gpt-transcribe` с серверным VAD,
  `gpt-live-transcribe` (`delay` minimal / low).

### 4. Итог по правилу п. 4

**Главное наблюдение — паузы обдумывания у пользователя 2,6–7,0 с (медиана 4,7 с), а не 1,5–2,5 с из брифа.**
Пользователь молчал, пока вспоминал продолжение фразы. Поэтому правило проверено дважды:
- **А** — на копиях записей, где каждая пауза укорочена до 1,5 / 2,0 / 2,5 с (из середины паузы вырезан кусок, голос и
  шум настоящие);
- **Б** — на записях как есть.

**Годных нет ни в А, ни в Б.** Всех валит ложный конец на паузе посреди мысли. Акустический детектор с задержкой ≤ 1,5 с
не отличает паузу 1,5–2,5 с от конца реплики. Требования «ложный конец ≤ 1 из 6» и «задержка ≤ 1,5 с» на таких паузах
противоречат друг другу.

Лучшие два (А) и что им мешает:
- **`semantic_vad high`**:
  - ложный конец 12 из 40 (тишина 3 из 6, улица 6 из 6, шум 3 из 6);
  - ложная речь на улице 2 из 2 (машины);
  - задержка 0,83 / 1,25 с, текст готов 1,41 с, точность 88 %.
- **Silero `p≥0.3 / 1250 ms`**:
  - ложный конец 18 из 40;
  - медиана задержки на улице 1,51 с — на волосок выше 1,5;
  - всё остальное проходит.

**Без пункта «ложный конец» во всех условиях проходит только Silero.** Это «нет конца 0», задержка в пределах и ложная
речь 0 из 8. Ложный конец по плану — забота S04 («отменяется, если ученик продолжил»). Например:

| Silero | задержка мед / p90, с | тишина / вода / улица / шум, мед, с | ложная речь | нет конца |
|---|---|---|---|---|
| p≥0.5 / 600 ms | 0,74 / 0,85 | 0,69 / 0,77 / 0,82 / 0,72 | 0 из 8 | 0 из 40 |
| p≥0.5 / 800 ms | 0,93 / 1,04 | 0,89 / 0,96 / 1,01 / 0,91 | 0 из 8 | 0 из 40 |
| p≥0.5 / 1000 ms | 1,17 / 1,26 | 1,11 / 1,21 / 1,23 / 1,13 | 0 из 8 | 0 из 40 |

Остальные не проходят даже так:
- **`server_vad`, `semantic_vad`** — ложная речь от машин на улице, 2 из 2.
- **WebRTC** — «нет конца» в воде и на улице (18–24 из 40) и ложная речь 6 из 8.
- **Нынешний порог 59 дБ / 3 с:**
  - в воде и на улице не кончает запись **ни разу** (10 из 10 — исходная жалоба подтверждена числами);
  - ложная речь 4 из 8;
  - задержка 3,06 с.

**Текст** (вопрос D62):

| Путь | Точность | Когда готов текст |
|---|---|---|
| Нынешний: файл в `gpt-transcribe` | 85 % | задержка детектора + запрос (0,89 с из облака; на телефоне в S02i 0,8–6,8 с) |
| `gpt-live-transcribe` `low` | 92 % | 0,46 с (p90 0,58) после `commit` |
| Сессия `gpt-transcribe` с серверным VAD | 85–90 % | 1,3–1,9 с после конца речи |

С Silero `p≥0.5 / 800 ms` текст через `gpt-live-transcribe` готов ≈ 0,9 + 0,46 ≈ 1,4 с после конца речи. Сейчас это
3,06 с + отправка и распознавание файла. Правило «серверный вариант лучше» к серверным VAD не применимо: они не годны из-за
ложной речи на улице.

**Маска после пульса (D34) не нужна.** Микрофон пульс почти не слышит: пик над фоном в медиане 2,2–2,9 дБ. У порога и у
Silero ложная речь с маской и без одинаковая.

**Вес на телефоне:**
- Silero нужен onnxruntime-android 1.32.0: на arm64 `libonnxruntime.so` 36 МБ, в APK +13,7 МБ, модель 2,2 МБ. Сейчас
  debug APK 12,7 МБ.
- WebRTC VAD (`android-vad`) — 37 КБ, но он не годен.

**Цена пробы.** По `usage` в ответах (секунды распознанного звука, вместе с пилотом) ≈ **$0,74**: сессии $0,44,
`gpt-live-transcribe` $0,23, разметка ≈ $0,05, файл ≈ $0,03. Моя оценка сверху (сессия по всей длине записи, вместе с
повтором после исправления стыка) — $1,06.

## Отклонения от брифа
- **Разметка конца речи** — по энергии в полосе речи. Метки `whisper-1` задают только окно поиска: сами по себе они
  ошибаются до 1,4 с (бриф разрешает «другой способ, если он точнее»).
- **Паузы укорочены в копиях записей** до 1,5–2,5 с, и правило проверено на них (раздел А отчёта пробы). Записи как есть —
  раздел Б. Причина — паузы пользователя 2,6–7 с вместо 1,5–2,5 с.
- **«Не больше 1 из 8» прочитано так:**
  - ложный конец — не больше 1 на условие среди реплик с паузой и длинных (их 6 на условие);
  - ложная речь — не больше 1 из 8 записей без речи всего (2 на условие × 4).
- **Добавлены WebRTC VAD и `gpt-live-transcribe`.** Последнему VAD на сервере не положен: конец — детектор на устройстве.
- **Ложный конец** = срабатывание раньше конца речи больше чем на 0,2 с (а не «раньше начала последнего слова»): метки
  начала слов в паузах ненадёжны.
- **`semantic_vad`** проверен в сессии транскрипции `gpt-transcribe` (как в S00b), а не в разговорной: так он даёт и текст.

## Ручная проверка для пользователя
Проверка уже пройдена записью всех 48 реплик. Если нужно повторить:
1. **(обязательно)** Сборка с нуля: `./gradlew clean installDebug`.
2. **(обязательно)** На экране практики нажмите **«🎙 Endpoint recordings (debug)»** → экран «Choose the condition» с
   четырьмя кнопками. Нажмите **«Silence (quiet room)»** → реплика «At noon.».
3. **(обязательно)** Средняя кнопка гарнитуры → слышно «говори» (две ноты вверх), потом тихое «тук» каждые 2 с. Скажите
   «At noon.», дождитесь двух «тук» и нажмите среднюю кнопку → «обрабатываю» (одна нота), на экране следующая реплика.
4. (желательно) **«← Conditions»**, затем **«← Close»** → обычный экран практики; **«Talk to Teacher 🎙️»** работает как
   раньше.
5. **(обязательно)** Запустите `tools/pull-log.sh` и пришлите файл в чат архитектора.

Что архитектор проверит по журналу:
- `[Debug] endpoint recording mode opened`;
- `[Debug] endpoint recording start (…)`;
- `[Debug] endpoint headset key … Talk` / `Stop Recording`;
- `[Debug] endpoint recording saved: …, ended by button, pulses N`.

## Замечено за пределами этапа
- **Длинные паузы обдумывания (до 7 с)** — естественны для ученика A1. S04 («отменить, если ученик продолжил») должен
  выдерживать паузы такой длины, а не только 1,5–2,5 с.
- **В режиме записи `AudioRecorder` пишет строку `[Audio] upload: wav N KB`**, хотя ничего не загружается. Строка
  безвредна, только в debug-режиме записи. Не чинил: это общий путь `uploadFile`.
- **Кнопка гарнитуры в режиме записи**, пока условие не выбрано или идёт сохранение, пишет
  `ignored (teacher is thinking or speaking)`. Текст из общего `HeadsetButton`; в режиме записи он неточен.
- **Пилот на синтезированном голосе:** `gpt-live-transcribe` с `delay: minimal` искажает короткие слова
  («Yes,terday», «I noon»); на голосе пользователя `low` точнее (92 % против 90 %).

## Вопросы к архитектору
1. **Правило п. 4 на паузах 1,5–2,5 с недостижимо для акустического детектора.** Принять ли для S03c Silero (например,
   `p≥0.5 / 800 ms`)? Ложный конец на паузе тогда переходит в S04 (ответ отменяется, если ученик продолжил).
   Альтернатива — длинная тишина (≥ 2,5 с) ценой задержки > 1,5 с.
2. **Вес:** onnxruntime-android добавит ≈ 13,7 МБ к APK (сейчас 12,7 МБ). Устраивает ли? Можно собрать урезанный
   onnxruntime только с операциями модели Silero — меньше, но сложнее сборка.
3. **Потоковый текст (D62):** `gpt-live-transcribe` — текст через 0,46 с после `commit`, точность 92 % против 85 % у файла.
   Цена $0,017/мин против $0,0045 (≈ 4 раза; при ≈ 3 мин речи ученика за занятие — ≈ $0,05). Брать ли в S03c вместе с
   Silero? Звук тогда идёт потоком во время записи; на ложном конце (пауза) нужен повторный `commit` — это пересекается с S04.
4. **Маску D34** в S03c убрать: микрофон пульс не слышит, маска ничего не меняет?
5. **Режим записи** оставить в debug для проверки S03c на тех же условиях или убрать?
