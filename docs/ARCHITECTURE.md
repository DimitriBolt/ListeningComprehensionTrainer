# Архитектура Listening Comprehension Trainer

Версия документа: 15 (2026-11-24). Меняет этот документ только чат-архитектор.
Исполнители этапов предлагают правки через свой отчёт.

## Цель приложения

Тренировка понимания английской речи на слух в голосовом диалоге с учителем.
Главная трудность ученика — слитная речь. Приложение делает её разборчивой
паузами между смысловыми группами и постепенно возвращает к естественной.

## Методика (главное правило учителя, с 2026-11-24)

Цель — **понимание на слух**, а не точный или полный ответ. Пользователь (ученик) формулирует так:
новые связи в мозгу образуются, только когда человек **вынужден отреагировать** на услышанное;
простое прослушивание, особенно на чужом языке, не учит.

- **Диалог, а не лекция.** Каждая реплика учителя кончается вопросом, на который ученик должен
  ответить. Лекция — это много фактов подряд без вопроса.
- **Но реплика содержательна** (D51, оценка пользователя после S02f: «переборщили с краткостью»).
  На старте — 3–4 простые фразы, ≈ 25–40 слов своего текста учителя, без поправки. В нём настоящее
  содержание: ответ с деталью, пример, маленький факт или история по теме. Каждая фраза — не длиннее
  ≈ 10 слов. Когда не понял — короче и проще.
- **Длина растёт по дням** (D56). Приложение помнит уровень ученика между разговорами. Уровень растёт,
  когда ученик долго понимает без «не понял», и снижается, когда «не понял» часто. Каждый уровень —
  на одну фразу (≈ 10 слов) длиннее предыдущего.
  Слишком короткая реплика («Hello! What do you like?») не даёт материала для слушания, и вопрос к
  ней не к чему привязать.
- **Вопрос растёт из сказанного** (D52). Типы вопросов чередуются:
  - проверка понимания — ответ есть в только что сказанном;
  - личный вопрос, связанный со сказанным.
- **Сначала уточни, потом отвечай.** «What is the temperature in Tucson?» → «Do you want to know
  the temperature at night or at noon?» Ученик вынужден распознать *temperature, night, noon*,
  а учитель по ответу видит, понял ли он.
- **Учитель обязан добиться полного понимания.** По ответу ученика учитель решает, понял ли тот.
  Не понял — повторить проще, другими словами, короче. Если и после двух упрощений не понял —
  одно ключевое слово по-русски, дальше снова по-английски (D43).
- **Уровень:** начать с A1 и подстраиваться — усложнять, когда ученик отвечает уверенно,
  упрощать, когда не понял (D42).
- **Поправка ошибок — сохранить** (оценка пользователя). Учитель сначала коротко говорит, как
  правильно звучала бы фраза или вопрос ученика: «I think you meant "What is the temperature in
  Tucson?", right?» — и потом продолжает диалог. Смысл этой фразы ученик уже знает (это его мысль),
  поэтому правильную форму он понимает на слух легко (D47).
  - С S02f поправку делает отдельный запрос — поправщик — одновременно с учителем (D53).
  - Поправляется только грамматика, произношение — нет (D54).
- Пауз и нарезки это правило не меняет: они уже работают (оценка пользователя).

## Условия, которые считаем постоянными

- Платформа: только Android (Samsung, реальное устройство). CLI-версия удаляется.
- Ученик всегда в наушниках. Эхоподавление не делаем.
- Запись ведётся со встроенного микрофона телефона, а не с Bluetooth-гарнитуры,
  чтобы наушники оставались в режиме качественного звука.
- Ключ OpenAI на компьютере пользователя лежит в `credentials.properties` в корне
  репозитория (строка `APIkey=...`). Файл в `.gitignore`. Читать его могут только
  сборка и локальные скрипты; печатать, логировать и коммитить ключ нельзя.
- На телефоне ключ хранится только на устройстве.
- Запись микрофона — PCM 16 кГц моно (подходит детекторам речи и загрузке файла).
  Если звук понадобится отправлять в Realtime API, пересчёт в 24 кГц делается на лету.

## Целевая структура

```
UI (Compose)            только рисует состояние и шлёт команды
   │
ConversationController  живёт в foreground-сервисе; машина состояний диалога
   │
   ├── AudioInput       микрофон → PCM 16 кГц моно; RecordedAudio (WAV + upload: AAC .m4a 32 кбит/с,
   │                    сжимается во время записи); предохранитель 90 с
   ├── TurnDetector     «ученик говорит / замолчал / закончил реплику»
   ├── Transcriber      transcribe(audio, prompt) → текст; gpt-transcribe, prompt = контекст + последняя фраза учителя
   ├── Tutor            Responses API, gpt-6-luna, поток, web_search (low), store: false;
   │                    reply(studentText, onEvent) → TutorEvent: Text | SearchStarted | SearchFinished |
   │                    Source | Done(stats); история — только реплики и вычищенные ответы, последние 30;
   │                    повтор решает контроллер (только пока ничего не прозвучало);
   │                    промпт — `app/src/main/resources/tutor_prompt.txt` (D46, его же читает
   │                    `tools/probe`); реплика кончается первым вопросом (D48); max_output_tokens 200 (D49)
   ├── StreamingSpeechPlanner  обёртка над SpeechPlanner: безопасная точка, `**…**` не режется,
   │                    пауза после группы берётся поздно (pauseAfter(i))
   ├── SpeechText       чистка сносок до нарезки; источники — только на экране (ConversationUi.sources)
   ├── Corrector        ResponsesCorrector: отдельный запрос без потока, одновременно с учителем, промпт
   │                    `app/src/main/resources/corrector_prompt.txt` (его читает проба); Correction —
   │                    проверка ответа (OK, та же фраза, непохожая — доля слов ученика < 0,5); ждать не
   │                    дольше 800 мс от начала ответа учителя; поправка звучит первой (D53)
   ├── NotUnderstood    счёт явных «не понял» подряд по истории учителя; служебная строка только
   │                    в запросе; русское слово — при счёте ≥ 3 (D55)
   ├── StudentLevel     (с S02h) уровень ученика, хранится на устройстве между разговорами; окно реплик
   │                    ученика → выше / ниже; цель длины — служебной строкой в запрос учителя (D56)
   ├── Retry / Failure  один повтор при сети, таймауте, 5xx, 429; FailureKind → голосовая фраза (D21)
   ├── HeadsetButton    медиа-сеанс сервиса; решение по состоянию (D29); дребезг 500 мс; долгое нажатие — системе
   ├── SpeechPlanner    текст учителя → смысловые группы и паузы (чистый Kotlin)
   ├── SpeechPipeline   start(scope, ReceiveChannel<SpeechChunk>): группы потоком по порядку, опережение 3,
   │                    сверка, повтор, запасной синтез; synthesizePrimary — для фразы «Let me check.»
   ├── Synthesizer      name, prepare(), synthesize(text) → SynthesizedSpeech (PCM + расшифровка), release()
   │                    реализации: RealtimeSynthesizer (основной), AndroidTtsSynthesizer (запасной)
   └── AudioOutput      prepareReply() → щит в мс по выходу звука; play(audio, shieldMs); сигналы;
                        listenPulseAllowed() — только наушники
```

Состояния контроллера: `Idle → Listening → Thinking → Speaking → Listening …`
плюс `Error` с голосовым сообщением и повтором последнего запроса.

Каждый компонент под контроллером — интерфейс. Смена модели или поставщика
означает новую реализацию интерфейса, а не правку контроллера.

## Эталон озвучки (текущее поведение, «золотой стандарт» Android)

Перенесено из прежнего `AGENTS.md`. Менять значения можно только осознанно, с записью
в журнал решений; при правках сначала думать о понимании ученика, потом о естественности.

- Смысловая группа: 3–5 слов, **жёсткий предел 6 слов**.
- Скорость речи: 0,88.
- Паузы после группы:

  | Где кончается группа | Пауза |
  |---|---|
  | конец абзаца (`\n`) | 1600 мс |
  | строка, целиком жирная (заголовок, D45) | 1100 мс |
  | конец предложения (`. ! ?`) | 1000 мс |
  | `, : ;` | 600 мс |
  | перед союзом / внутри предложения | 250 мс |

- Номер пункта списка (`1.`) — отдельная группа, пауза после него **400 мс**, затем заголовок
  (D22; до S02b номер и заголовок были одной группой и сливались на слух).
- Группа всегда содержит хотя бы одну букву или цифру; одиночный знак (`:`, `.`, `!`, `-`)
  присоединяется к предыдущей группе (D23).
- **Щит Bluetooth.** Наушники засыпают в паузах и съедают начало следующей группы.
  С S02: 1200 мс локальной тишины (нули) перед группой и запуск группы на 1200 мс раньше —
  **только** когда звук идёт в Bluetooth или выход неизвестен. Проводные и динамик — без щита (D17).
- Громкость: голос нормализуется по звучащим окнам, пик не выше −1 дБFS; целевой уровень —
  в D25. Сигналы чуть тише голоса.
- Поведение учителя — по разделу «Методика» (с S02e); прежние уровни A2/B1/B2 отменены.

Пользователь занимается, не глядя на экран (D13). Сигналы генерируются в приложении
(`audio/CueTones.kt`), когда играть — решает контроллер.

| Событие | Сигнал | Как звучит |
|---|---|---|
| началась запись (оба режима) | «говори» | две ноты вверх, 880 → 1320 Гц, 0,19 с; запись начинается после него |
| запись с речью закончена | «обрабатываю» | одна нота 660 Гц, 0,12 с |
| ждём учителя дольше 5 с | «тик» | щелчок 1200 Гц, 25 мс, на 10 дБ тише; каждые 3 с |
| идёт запись (с S03) | «пульс» | мягкое «тук» 520 → 390 Гц, 60 мс, затухает; каждые 2 с от начала записи; только в наушниках (D28); куски записи 350 мс после пульса не идут в уровень и правило тишины |
| ученик ничего не сказал | «не услышал» | две одинаковые ноты 494 Гц, 0,29 с |
| ошибка | «ошибка» | две низкие жужжащие ноты 196 → 185 Гц, 0,40 с; за ней всегда «конец» |
| разговор окончен, ждать нечего | «конец» | три ноты вниз 784 → 659 → 523 Гц, 0,42 с; на каждом выходе из круга |

## Инварианты (нарушать нельзя ни на одном этапе)

1. **Принцип чанков.** Речь учителя дробится на короткие смысловые группы.
   Укрупнение запрещено. Резать внутри устойчивого сочетания тоже нельзя.
2. **Скорость.** Время от конца записи ученика до первого слышимого звука учителя не должно
   расти. Меряется по строкам `[Timing]` журнала (медиана и худший случай), не секундомером.
   Цель (D44): первый звук учителя (фраза или ответ) — медиана ≤ 4 с всегда; сам ответ с поиском ≤ 7 с.
3. **Логика отдельно от Android.** Разбиение текста, машина состояний, правила
   конца реплики — чистый Kotlin с модульными тестами.
4. **Модели в одном месте.** Все идентификаторы моделей и адреса API — в одном
   файле конфигурации.
5. **Секреты.** Ключи, токены и записи голоса в репозиторий не попадают.
6. **Мелкие шаги.** Этап делает только то, что в его брифе.
7. **Приложение собирается** после каждого коммита в `master`.
8. **Журнал.** Каждый выход из круга пишется в журнал строкой `circle end: <ПРИЧИНА> (...)`.
   Формат строки: время с мс и поясом, `[Источник]`, событие. Источники: `Process`, `Activity`,
   `UI`, `Service`, `Controller`, `Timing`, `Audio`, `Network`, `Crash`. В журнал никогда не

   журналу, проверяется по журналу, а не просьбой к пользователю.
